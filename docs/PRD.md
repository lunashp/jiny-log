# PRD — 지니로그 (jiny-log)

- 작성일: 2026-08-17
- 상태: 초안 (구현 착수 전)

---

## 1. 한 줄 정의

코드를 쓰면서 얻은 인사이트와 트러블슈팅 기록을 쌓는 개인 기술 블로그. **검색엔진과 AI 어시스턴트가 인용하기 좋은 형태**로 발행되며, 사람이 길게 읽어도 피로하지 않은 에디토리얼 디자인을 갖는다.

## 2. 왜 만드는가

세 가지 문제를 동시에 푼다.

1. **기록의 휘발.** 디버깅으로 알아낸 것들이 어디에도 남지 않고 사라진다. 같은 문제를 6개월 뒤 다시 겪는다.
2. **검색되지 않는 기록.** 노션·로컬 메모에 적어봤자 나 말고는 아무도, 그리고 미래의 나조차 찾지 못한다.
3. **AI 시대의 도달 경로 변화.** 개발자가 에러 메시지를 구글이 아니라 ChatGPT/Claude/Perplexity에 붙여넣는 비율이 계속 오르고 있다. **AI가 답변을 만들 때 인용되지 않는 글은 사실상 존재하지 않는 글**이 된다. 전통적 SEO만으로는 이 표면을 못 잡는다.

→ 그래서 SEO(검색 결과 노출)와 **GEO(생성형 엔진에서의 인용)** 를 동급의 1급 요구사항으로 둔다.

## 3. 대상 독자

| 순위 | 독자 | 상황 |
|---|---|---|
| 1 | **에러 메시지를 검색한 개발자** | 구글/AI에 에러 문구를 던졌고, 정확히 그 문제를 다룬 글을 찾는 중. 체류 시간 짧고 목적 뚜렷 |
| 2 | **AI 어시스턴트** | 사용자 질문에 답하려고 이 페이지를 크롤·인용. 사람이 아니지만 실질적으로 가장 중요한 "독자" |
| 3 | **미래의 나** | 6개월 뒤 같은 문제를 다시 만난 본인 |
| 4 | 기술적 관심으로 유입된 동료 개발자 | 목록에서 흥미로운 제목을 눌러 들어옴 |

1번과 2번이 설계를 지배한다. **글은 "위에서부터 순서대로 읽는 사람"이 아니라 "특정 답만 찾아 스캔하는 대상"을 기준으로 구조화**한다.

## 4. 콘텐츠 유형

`category` 열거형과 1:1 대응한다.

| 유형 | 내용 | 비중 목표 |
|---|---|---|
| `troubleshooting` | 증상 → 원인 → 해결. 에러 메시지가 제목에 들어감 | 50% |
| `insight` | 구현하며 얻은 판단·패턴·트레이드오프 | 30% |
| `note` | 짧은 발견, 팁, 버전 변경 메모 | 15% |
| `retrospective` | 프로젝트 회고 | 5% |

## 5. 언어 정책

- **한국어 + 영어 이중 언어.** `content/posts/{ko,en}/<slug>.mdx`
- 모든 글을 양쪽으로 쓸 의무는 없다. **ko만 존재하는 글이 정상 상태**다.
- 영어 번역의 우선순위: `troubleshooting` > `insight` > 나머지. 에러 메시지 기반 글이 영어권 도달 가치가 가장 크다.
- UI 문자열은 양 로케일 모두 완비한다 (`messages/{ko,en}.json`).

## 6. 성공 지표

발행 초기 6개월 기준. **순위나 트래픽 총량이 아니라 "인용 가능한 상태로 계속 쌓이는가"를 본다.**

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| **발행 빈도** | 월 2편 이상 | 저장소 커밋 |
| **AI 크롤러 히트** | 신규 글이 발행 2주 내 GPTBot/ClaudeBot/PerplexityBot 중 2종 이상에 크롤됨 | Vercel 로그 UA 분석 |
| **AI 리퍼러 세션** | 6개월 시점 전체 세션의 10%+ | chatgpt.com / perplexity.ai / claude.ai / copilot.microsoft.com 리퍼러 세그먼트 |
| **Core Web Vitals** | 전 페이지 LCP<2.5s, INP<200ms, CLS<0.1 | Vercel Speed Insights (필드 데이터) |
| **인덱싱** | 발행 1주 내 색인 | Search Console |
| **접근성** | 자동 검사 위반 0 | Playwright + axe |

> **AI 리퍼러 측정의 알려진 한계:** AI 어시스턴트 경유 방문의 상당 부분이 리퍼러 헤더 없이 도착해 "Direct"로 오분류된다. 업계 공통 문제이며 깔끔한 해법이 없다. 따라서 **크롤러 히트 로그를 1차 신호, 리퍼러 세션을 2차 신호**로 취급한다. 리퍼러 숫자만 보면 과소평가된다.

**의도적으로 지표에서 뺀 것:** 페이지뷰 총량, 체류 시간, 이탈률. 트러블슈팅 글은 "빨리 답 찾고 나가는 것"이 성공이라 체류·이탈 지표가 품질과 역상관이다.

## 7. 범위

### v1 (첫 배포에 포함)

- ko/en 로케일 라우팅, 언어 전환
- 글 목록 / 본문 / 태그별 목록 / 홈
- MDX 렌더링 + 허용 컴포넌트 4종 (`Callout`, `Figure`, `Aside`, `Details`)
- 목차(TOC), TL;DR 블록, 코드 하이라이팅 + 복사 버튼
- 메타데이터·canonical·hreflang·OG/Twitter 카드
- 글별 동적 OG 이미지 (cover 가 있으면 배경으로 사용)
- 본문 리드 이미지 (cover, 빌드 타임 치수 해석으로 CLS 0)
- `sitemap.xml`, `robots.txt`, RSS, `llms.txt`, 글별 raw markdown
- JSON-LD: `BlogPosting`, `Person`, `WebSite`+`SearchAction`, `BreadcrumbList`
- 다크/라이트 테마
- Vercel Analytics + Speed Insights

### v2 이후 (지금 만들지 않음)

- 사이트 내 검색
- 댓글 (giscus 등)
- 뉴스레터 구독
- 시리즈 전용 인덱스 페이지 (`series` 필드는 계약에 있으나 **현재 렌더되지 않음**)
- 조회수 표시
- 관련 글 자동 추천 (v1은 frontmatter `related` 수동)

### 명시적 비목표

- **CMS / 관리자 UI.** 글은 `blog-publisher` MCP를 통해 들어온다. 웹 에디터를 만들지 않는다.
- **다중 저자.** 1인 블로그다. `Person` 스키마는 단일 저자 전제.
- **광고·수익화.** 성능과 독서 경험을 해친다.
- **프레임워크 쇼케이스.** 이 저장소는 기술 자랑용이 아니라 글을 내보내는 도구다. 화려하지만 느린 선택을 하지 않는다.

## 9. 핵심 전제

**GEO 성과의 최대 변수는 기술이 아니라 글 자체의 구조다.** 사이트맵·JSON-LD·llms.txt를 완벽하게 갖춰도 글이 결론을 앞에 두지 않고, 버전을 명시하지 않고, 출처를 인용하지 않으면 인용되지 않는다. 따라서 [`WRITING-GUIDE.md`](./WRITING-GUIDE.md) 는 부속 문서가 아니라 **이 프로젝트의 핵심 산출물**이다.
