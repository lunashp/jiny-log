2년전 쯤 기획만 하고 흐지부지 되었던 프로젝트를 다시 살려내서 해보기
프로젝트가 어느정도 진행 된 후에 쓰는 글이라 기억이 안나는 내용들도 있어서 아쉽다

## 기획의도
바쁘다 바빠 현대사회에 쉼이 될 수 있는 것은 무엇이 있을까?
남들에게 털어놓지 못하는 이야기를 익명으로 이야기할 수 있는 창구가 필요하다고 생각했다.
익명의 상대에게 이야기를 전하고 위로를 전하는 창구가 되도록 하는 것이 시크릿 톡의 목표이다.


## 사용기술
- typescript
- react 18
- next 14.1.2
- next-auth 4.21.1
- mongodb 4.17.2

>js 로 초반 구성 후 ts로 전체 구성을 변경 했는데 의존성에 버전 충돌 때문에 마음이 아팠다. 처음 기술 구성은 저게 아니었으나 프로젝트 진행해 가면서 버전 변경을 좀 했다.

## DB설계

## 초기 스키마

`users`

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| `_id` | ObjectId | 고유 사용자 식별자 |
| `name` | String | 사용자명 |
| `email` | String | 이메일 주소 |
| `password` | String | 비밀번호 |

`letters`

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| `_id` | ObjectId | 고유 편지 식별자 |
| `sender_id` | ObjectId | 송신자 사용자 식별자 |
| `recipient_id` | ObjectId | 수신자 사용자 식별자 |
| `content` | String | 편지 내용 |
| `sent_at` | Date | 편지 작성 일시 |
| `is_read` | Boolean | 편지를 읽었는지 여부 |
| `is_archived` | Boolean | 편지를 보관했는지 여부 |

`mailbox`

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| `_id` | ObjectId | 고유 우편함 식별자 |
| `user_id` | ObjectId | 사용자 식별자 |
| `letter_id` | ObjectId | 우편함에 포함된 편지 식별자 |
| `is_sent` | Boolean | 사용자가 보낸 편지인지 여부 |
| `is_received` | Boolean | 사용자가 받은 편지인지 여부 |

## 구현하면서 바뀐 것 (`letters`)

위 표는 초창기 구성이고, 실제로 만들면서 `letters` 가 아래처럼 달라졌다.

| 초기 | 변경 후 | 이유 |
| --- | --- | --- |
| `sender_id` | `send_user_id` | 이름만 정리 |
| `recipient_id` | `receive_user_id` | 이름만 정리 |
| `content` | `message` | 이름만 정리 |
| `sent_at` | `send_date` | 이름만 정리 |
| `is_archived` | (삭제) | 보관 기능을 쓰지 않게 됐다 |
| — | `title` (추가) | 편지함 목록에서 제목이 보이는 편이 나았다 |
| — | `del_at` (추가) | 소프트 삭제 |
| — | `report_at` (추가) | 신고당한 사용자의 편지를 숨기고, 신고가 일정 횟수를 넘으면 추가 조치(추후 관리자 role)로 이어지게 하려고 |
